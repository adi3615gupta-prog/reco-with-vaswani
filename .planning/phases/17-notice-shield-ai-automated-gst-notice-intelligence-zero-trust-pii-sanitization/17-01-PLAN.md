# Plan 17-01: Zero-Trust PII Sanitization Engine & Ingestion Pipeline

## Goal
Build and verify the data ingestion and Zero-Trust PII Sanitization layer:
1. Local PDF notice text extractor using `pdf-parse` and multi-destination crawler integration.
2. Deterministic two-way regex & NER tokenization engine (`piiSanitizer.ts`) scrubbing GSTINs, PANs, ARNs, names, and contact details with an in-memory session map.
3. Preserving all statutory sections, dates, financial years, and ₹ amounts intact.
4. Deterministic local re-hydration engine restoring real client details upon return.
5. Automated Vitest unit test suite proving 100% masking and zero data leakage.

---

## Tasks
- [x] **Task 1: Deterministic Zero-Trust PII Tokenizer & Re-Hydrator (`src/lib/piiSanitizer.ts`)**
  - Scrub GSTINs (`/\b\d{2}[A-Z]{5}\d{4}[A-Z]{1}[1-9A-Z]{1}Z[0-9A-Z]{1}\b/g`) $\to$ `{{GSTIN_TOKEN_n}}`.
  - Scrub PANs (`/\b[A-Z]{5}\d{4}[A-Z]{1}\b/g`) $\to$ `{{PAN_TOKEN_n}}`.
  - Scrub ARNs and DINs $\to$ `{{ARN_TOKEN_n}}`.
  - Scrub Names, Emails, and Phones $\to$ `{{ENTITY_LEGAL_NAME_TOKEN}}`, `{{CONTACT_TOKEN}}`.
  - Maintain session map in-memory `Map<sessionId, { tokenToReal, realToToken }>`.
  - Support bracket variants in `rehydrateDraft`.

- [x] **Task 2: Backend Upload & PDF Extraction Route (`notices_routes.js`)**
  - Implement `POST /api/notices/upload-pdf` with `multer` memory storage.
  - Parse PDF buffers using `pdf-parse` (`PDFParse` class).
  - Extract detected GSTIN, reference number, notice type, and amounts.
  - Upsert notice into SQLite database `gst_notices`.

- [x] **Task 3: Unit Testing & Invariant Verification (`src/test/piiSanitizer.test.ts`)**
  - Verify all sensitive identifiers are completely absent from sanitized payload.
  - Verify statutory sections, dates, and ₹ amounts are preserved.
  - Verify re-hydration accurately swaps tokens back to actual values.
