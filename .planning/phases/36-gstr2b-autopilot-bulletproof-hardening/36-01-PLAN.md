<threat_model>
<threat>
  <id>T-36-01</id>
  <description>Golden Rule Violation & Cross-Year Clobbering: Current `POST /api/gstr2b/cancel` (`gstr2b_routes.js:519-525`) runs `return_period LIKE '%Month%'`, which overwrites `SYNCED` or `NIL_SYNCED` batches and hits other financial years (e.g. `April 2024` when cancelling `April 2025`).</description>
  <mitigation>Replace wildcard `LIKE` with `buildStrictPeriodFilter(p)` from `gstr2b/db.js` and enforce `AND COALESCE(status, 'PENDING') NOT IN ('SYNCED', 'PUSHED_TO_3B', 'NIL_SYNCED')` on `UPDATE gstr2b_batches`.</mitigation>
</threat>
<threat>
  <id>T-36-02</id>
  <description>Truncated Download Silently Marked Clean: A partial download or empty parse could overwrite valid existing GSTR-2B invoices or appear cleanly `SYNCED` when portal summary totals differ.</description>
  <mitigation>Preserve `bulkSaveGstr2bInvoices` early return on `invoices.length === 0`, enforce `verifyParsedGstr2bPayload` GSTIN/period match before ingesting, and record `verify_status = 'PARTIAL_VERIFY'` + `verify_warning` via `verifyGstr2bBatchChecksum` without deleting valid rows.</mitigation>
</threat>
<threat>
  <id>T-36-03</id>
  <description>Cross-Module Contract Regression (`returns_storage_routes.js:2747`): Changing `gstr2b_batches.status` away from `'SYNCED'` / `'NIL_SYNCED'` would break `returns_storage_routes.js` compliance matrix detection and `push-to-3b`.</description>
  <mitigation>Store checksum state in dedicated `verify_status` / `verify_warning` columns while preserving `status = 'SYNCED'` (or `'NIL_SYNCED'` / `'PUSHED_TO_3B'`). Reversibility: **Reversible** (`ALTER TABLE ... ADD COLUMN` with defaults; status enum unchanged).</mitigation>
</threat>
</threat_model>

- **Batch Status Contract:** Preserving `gstr2b_batches.status` as `'SYNCED'` / `'NIL_SYNCED'` / `'PUSHED_TO_3B'` keeps `returns_storage_routes.js:2663, 2747` and `push-to-3b` 100% intact. Reversibility: **Reversible** (no breaking status enum change).
