# Plan 25-01: GSTR-1 Canonical Data Model, Auto-Classification Engine, TaxPower Tally Normalizer & Official Offline JSON Generator

## Goal
Implement a complete TypeScript GSTR-1 Outward canonical engine ([`src/lib/gstr1Engine.ts`](file:///D:/My%20software/full%20and%20final/gst%20consolidater/reco-with-vaswani-main/src/lib/gstr1Engine.ts)) that models all outward supply tables, provides automated statutory classification from raw sales vouchers/invoices (handling the post-August 2024 ₹1,00,000 B2CL threshold, delinked CDNR, and HSN B2B/B2C split), integrates reverse-engineered **TaxPower GST** normalization capabilities (All-In-One flat sales register parser, Tally UQC dictionary mapping, Table 13 document series gap analyzer, and 3-tier POS state resolver), and generates 100% portal-compliant GSTR-1 JSON payloads identical to those produced by `GST Offline Tool.exe` Release 3.2.4.

---

## Tasks

- [ ] **Task 1: Canonical Type Definitions & Data Model (`src/lib/gstr1Engine.ts`)**
  - Define complete TypeScript interfaces for GSTR-1 tables:
    - `Gstr1B2BInvoice`, `Gstr1B2BGroup`
    - `Gstr1B2CLInvoice`, `Gstr1B2CLGroup` (inter-state unregistered > ₹1,00,000)
    - `Gstr1B2CSItem` (consolidated inter-state $\le$ ₹1,00,000 or intra-state unregistered)
    - `Gstr1CdnrNote`, `Gstr1CdnurNote` (delinked note structures without mandatory original invoice fields)
    - `Gstr1ExportInvoice` (with/without payment, shipping bill, port code)
    - `Gstr1AdvanceItem`, `Gstr1AdvanceAdjustedItem`
    - `Gstr1ExemptSupplies` (Nil, Exempt, Non-GST)
    - `Gstr1HsnItem` (bifurcated into `hsn_b2b` and `hsn_b2c` with UQC, quantity, taxable value, tax split)
    - `Gstr1DocItem` (serial ranges: from, to, total, cancelled, net)
    - `Gstr1EcoSupplies` (Tables 14 and 15)
    - `Gstr1ReturnData` (aggregate root for the return period)

- [ ] **Task 2: TaxPower Normalization Suite (UQC Mapper, Table 13 Gap Analyzer, POS State Resolver)**
  - **Tally UQC / Unit Mapping Dictionary (`tallyUnitUqcMap`):**
    - Implement comprehensive unit normalization mapping arbitrary Tally units (`PCS`, `NOS`, `BOX`, `KGS`, `MTR`, `DOZ`, `BAG`, `SET`, `ROLL`, `CAN`, `BTL`, `PAC`, `QTL`, `TUB`, `BND`, `PRS`, `THD`, `SQF`, `SQM`, `LTR`, `GMS`, `TON`, etc.) to official GSTN 3-letter UQC codes (`NOS-NUMBERS`, `KGS-KILOGRAMS`, `BOX-BOX`, etc.) to prevent Table 12 portal validation rejection.
  - **Table 13 Document Series Gap Analyzer (`TallyDocIssuedMapper`):**
    - Implement regex-based serial decomposition (`^([A-Za-z0-9\/\-_]*?)(\d+)([A-Za-z0-9\/\-_]*)$`) on consecutive sales voucher numbers.
    - Group by series prefix/suffix, detect starting serial (`from`), ending serial (`to`), total count, missing integers in sequence (flagged as `canc` cancelled documents), and compute `net_issue`.
  - **Place of Supply (POS) State Resolver (`TallySalesStateResolver`):**
    - Implement 3-tier fallback when voucher POS is missing: (1) Buyer GSTIN first 2 digits, (2) Buyer State / Consignee State name mapped to 2-digit GST state code, (3) Supplier state (intra-state fallback).

- [ ] **Task 3: Automated Statutory Classification Engine & All-In-One Flat Ingestion**
  - Implement `classifyOutwardInvoices(salesInvoices, returnPeriod, clientGstin)`:
    - Determine period cut-off: if return period $\ge$ August 2024, set B2CL threshold = `100000`; otherwise `250000`.
    - If customer has valid GSTIN $\to$ route to `b2b`.
    - If customer has no GSTIN (unregistered):
      - If recipient POS $\neq$ supplier state AND invoice value > threshold $\to$ route to `b2cl`.
      - Otherwise $\to$ aggregate into `b2cs` grouped by `(pos, rate, type)`.
    - Route Credit/Debit notes:
      - If registered customer $\to$ `cdnr`.
      - If unregistered customer $\to$ `cdnur`.
    - Auto-generate bifurcated HSN summary (`hsn_b2b` vs `hsn_b2c`) from itemized lines, validating 4-digit or 6-digit HSN length based on client turnover.
    - Compute summary aggregates for reconciliation against GSTR-3B Table 3.1.
  - Implement **All-In-One Flat Ingestion Parser** (Compatible with TaxPower GST `GSTR1-AllInOne.xlsx` and standard ERP registers):
    - Ingests single-sheet outward supplies (`Sales` sheet with 26 columns: Receiver GSTIN, Inv No, Date, Value, HSN/SAC, Qty, UQC, POS, Export fields) and single-sheet notes (`CDN`).
    - Automatically classifies every line into B2B, B2CL, B2CS, EXP, and HSN without requiring users to split into 32 separate sheets manually.

- [ ] **Task 4: 100% Portal-Compliant JSON Generator**
  - Implement `generateGstr1PortalJson(data: Gstr1ReturnData, clientProfile: any, options?: any): string`:
    - Generates stringified JSON matching the exact schema extracted from `GST Offline Tool.exe`:
      - `"gstin"`, `"fp"` (format `MMYYYY`), `"version": "GSTR1_V3.2.4"`, `"hash"`
      - `"b2b"`, `"b2ba"`, `"b2cl"`, `"b2cla"`, `"b2cs"`, `"b2csa"`, `"nil"`, `"exp"`, `"expa"`
      - `"cdnr"`, `"cdnra"`, `"cdnur"`, `"cdnura"`
      - `"at"`, `"ata"`, `"atadj"`, `"atadja"`
      - `"doc_issue"`
      - `"hsn": { "hsn_b2b": [...], "hsn_b2c": [...] }`
      - `"supeco"`, `"supecoa"`, `"ecom"`, `"ecoma"`
    - Enforce validation rules:
      - Item counts $\le 19,000$ per file.
      - If payload exceeds 5 MB, support chunked generation (`generateGstr1PortalJsonChunks`).
      - POS must be 2-digit numeric string (e.g. `"27"`).
      - Amounts formatted to 2 decimal places.

- [ ] **Task 5: Unit Testing & Verification**

    - Test delinked CDNR mapping.
    - Test bifurcated HSN generation.
    - Test Tally UQC mapping and Table 13 document gap calculation.
    - Test All-In-One flat register parsing.
    - Test JSON payload matches official schema and validates successfully.
