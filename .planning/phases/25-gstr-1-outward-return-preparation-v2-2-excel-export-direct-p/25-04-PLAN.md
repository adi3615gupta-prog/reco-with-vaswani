## Tasks

- [ ] **Task 1: Configurable Reconciliation Settings Model & UI Dialog (`src/lib/reconciliation.ts` & `src/pages/Reconciliation.tsx`)**
  - Expand `ReconciliationOptions` interface in `reconciliation.ts` with TaxPower settings:
    ```typescript
    export interface ReconciliationOptions {
      mode?: 'input' | 'output';
      tolerance?: number;                    // ₹0, ₹1, ₹2, ₹5, ₹10 (default: 2)
      partyTolerance?: number;               // (default: 5)
      considerPreviousYearInvoices?: boolean; // include in matching vs route to Prior FY bucket
      filterType?: 'documentDate' | 'documentPeriod';
      considerInvoicesNextPeriod?: boolean;  // detect timing differences for subsequent period 2B filings
      considerITCNotAvailable?: boolean;     // filter out GSTR-2B invoices where itcavl === 'N'
      documentNoMatchType?: 'exact' | 'fuzzy' | 'coreSerial';
      considerRCMInvoices?: boolean;         // include or isolate RCM supplies
      onProgress?: (stage: string, percent: number) => void;
    }
    ```
  - Implement options handling inside `reconcile()`:
    - If `considerPreviousYearInvoices === false`, route prior FY invoices to `Prior FY (Excluded)`.
    - If `considerITCNotAvailable === false`, exclude ineligible 2B invoices from matching.
    - If `considerInvoicesNextPeriod === true`, identify invoices matching next period portal filings and tag as `Timing Difference (Next Period)`.
  - Build an Obsidian Glass "Reconciliation Settings" modal in `Reconciliation.tsx`:
    - Tolerance slider (₹0 to ₹10).
    - Toggles: "Include Prior FY Invoices", "Detect Next Period Timing Differences", "Exclude ITC Not Available Records", "Include RCM Records".
    - Matching Mode radio selector: "Exact Only", "Fuzzy Alphanumeric", "Full Multi-Pass Waterfall".
    - Persist user choices in SQLite `app_config` and `localStorage`.

- [ ] **Task 2: Rule 88A Mathematical Cash Liability Set-Off Optimizer (`src/lib/rule88aOptimizer.ts`)**
  - Implement `optimizeRule88ASetOff(liability: TaxLiability, itc: ItcBalances): Rule88ASetOffResult`:
    - Exactly mirrors decompiled TaxPower `OpLiab2`, `UtilITCReqVO`, and `UtilCsshReqVO` model:
      - **Step 1:** Exhaust IGST credit against IGST liability (`igst_igst_amt`).
      - **Step 2:** Formulate linear distribution of remaining IGST credit between CGST (`igst_cgst_amt`) and SGST (`igst_sgst_amt`) to minimize total cash liability (accounting for asymmetric CGST/SGST balances).
      - **Step 3:** Apply CGST credit towards remaining CGST liability (`cgst_cgst_amt`), then remaining IGST liability (`cgst_igst_amt`) (never SGST).
      - **Step 4:** Apply SGST credit towards remaining SGST liability (`sgst_sgst_amt`), then remaining IGST liability (`sgst_igst_amt`) (never CGST).
      - **Step 5:** Compute net cash ledger payment needed (`net_cash_igst`, `net_cash_cgst`, `net_cash_sgst`) and remaining ITC ledger balances.
  - Wire a 1-click **"⚡ Auto-Optimize Rule 88A Set-Off"** button in `Gstr3bWorkingSheet.tsx` that populates the optimal set-off table and updates net cash payable figures dynamically.

- [ ] **Task 3: E-Way Bill vs GSTR-1 Outward Supply Cross-Checker (`src/lib/ewbRecoEngine.ts`)**
  - Implement `reconcileEwbWithGstr1(ewbRecords: EwbRecord[], gstr1Invoices: Gstr1B2BInvoice[], options?: any)`:
    - Matches E-Way Bills against GSTR-1 invoices by Document Number, Date, Recipient GSTIN, and Invoice Value (with tolerance).
    - Flags:
      - **EWB Missing:** Invoices with value > ₹50,000 (inter-state) or state-specific threshold without an active E-Way Bill.
      - **GSTR-1 Omission:** Valid E-Way Bills generated on portal with no corresponding outward invoice reported in GSTR-1 (tax evasion / omission risk).
      - **Value Mismatch:** Value discrepancies between E-Way Bill and GSTR-1 invoice.
    - Generates a Zero-Merge audit report `EWB_vs_GSTR1_Reconciliation.xlsx` with clean sorting and filtering.
