## 1. System Classification

**System Type:** Conversational Assistant & In-App Statutory Copilot (Hybrid Chat with Structured Action Dispatch)

**Description:**
"Sourav" is an in-app AI compliance assistant and software co-pilot embedded in the "AUDIT WITH VASWANI" desktop suite. Designed specifically for Indian Chartered Accountants, Tax Auditors, and Finance Managers, Sourav answers technical GST and accounting legal queries, guides users through all 12 modules of the software, and emits clickable deep-link buttons (`[ACTION:navigate:<target>]`) that allow 1-click navigation to relevant reconciliation and return filing consoles.

**Critical Failure Modes:**
1. **Statutory Hallucination:** Fabricating non-existent CGST/SGST Act sections, quoting incorrect GST tax rates, or misstating statutory filing deadlines (e.g. hallucinating a fictional section number or incorrect interest calculation under Section 50).
2. **Context Bleed / Entity Confusion:** Referencing invoices or data from Client A while Client B is active in the current app session.
3. **Malformed Navigation Actions:** Emitting broken or unregistered action tags that crash or corrupt frontend navigation state.
4. **Credential / Key Leakage:** Leaking the Google Gemini API key or taxpayer GST portal passwords into the chat output or frontend response payloads.

## 1b. Domain Context

**Industry Vertical:** Indian Taxation, Statutory Audit & Corporate Compliance (GST, Income Tax, TDS, Schedule III Financial Statements)

**User Population:** Chartered Accountants (CAs), Article Assistants, Tax Auditors, Corporate Controllers, Tax Advocates.

**Stakes Level:** **Critical / High**

**Output Consequence:** Taxpayers rely on these answers to claim Input Tax Credit (ITC), file statutory GSTR-3B/1 returns, calculate tax liabilities, and draft legal replies to GST department demand notices (DRC-01, ASMT-10). Incorrect advice can lead to recovery notices with 18% or 24% interest liability under Section 50 and penalties under Section 73/74.

### What Domain Experts Evaluate Against

| Dimension | Good (Expert Accepts) | Bad (Expert Flags) | Stakes | Source |
|---|---|---|---|---|
| **Statutory Precision** | Cites exact section (e.g. Sec 16(2)(aa) CGST Act for 2B matching, Sec 17(5) for blocked credit, Sec 16(4) for annual cut-off). | Generic statements like "as per the new law" without citing specific legal sections or circulars. | Critical | CGST Act 2017 & CBIC Circulars |
| **Return Mechanics Alignment** | Distinguishes between GSTR-2B (static basis for ITC) and GSTR-2A (dynamic), Table 4(A)(5) vs Table 4(B) reversals. | Confusing GSTR-2A with GSTR-2B or advising 3B amendments (which are statutorily impossible). | Critical | Rule 88A & CGST Rules |
| **Code-Switching Naturalness** | Understands mixed Hindi-English phrasing ("2B me mismatch aa raha hai") and replies in polite, technically accurate Hinglish. | Broken literal translations or robotic robotic responses that distort legal meaning. | Medium | User Workflow Reality |
| **Action Grounding** | Provides exact module names and supplies valid `[ACTION:navigate:xxx]` tags matching the 12 software modules. | Telling the user to click a non-existent button or directing them to wrong menus. | High | Codebase Architecture Manual |

### Known Failure Modes in This Domain
- **Section Conflation:** Confusing Section 16(4) (cut-off date for ITC claim: 30th November) with Section 16(2) (eligibility conditions).
- **RCM Ambiguity:** Suggesting ITC can be claimed on reverse-charge supplies without first paying tax in cash (violating Section 49(4)).
- **Rule 37 vs 37A:** Reversals for 180-day non-payment to suppliers (Rule 37) vs supplier non-filing of GSTR-3B (Rule 37A).

### Regulatory / Compliance Context
- Central Goods and Services Tax (CGST) Act, 2017
- Integrated Goods and Services Tax (IGST) Act, 2017
- CGST Rules, 2017 (Rule 37, 37A, 42, 43, 88A, 88C, 88D)
- IT Act, 1961 (TDS Sections 194C, 194J, 194I, 194Q, 206AB; Section 115BAC)
- ICAI Code of Ethics & Standards on Auditing (SA)

## 2. Framework Decision

**Selected Framework:** `@google/generative-ai` (Official Google GenAI SDK for Node.js)

**Version:** `^0.21.0`

**Rationale:**
1. **Lightweight & Zero-Bloat:** The desktop application is packaged using Electron and Node.js. Using the direct official SDK adds < 500 KB to the bundle, compared to heavy multi-megabyte frameworks like LangChain.
2. **First-Party Support for Gemini 2.0 Flash:** Native support for `gemini-2.0-flash` with optimized streaming, system instruction overrides, and multi-turn chat sessions (`startChat`).
3. **No Python Dependency:** Python frameworks (CrewAI, LlamaIndex Python) would require shipping a full Python runtime inside the Windows installer (`.exe`), ballooning file size and causing DLL conflicts.
4. **Deterministic System Instructions:** Ephemeral system instructions can be re-generated on every user request without altering or polluting multi-turn conversational history.

**Alternatives Considered:**

| Framework | Ruled Out Because |
|---|---|
| **LangChain.js (`@langchain/core`)** | Excessive abstraction layers, complex class hierarchies, slow initialization times, and frequent breaking changes between minor versions. |
| **CrewAI / AutoGen** | Python-only frameworks. Requiring Python would break the standalone Node.js / Electron distribution model of AUDIT WITH VASWANI. |
| **OpenAI Agents SDK** | Ties the software to OpenAI API pricing and lacks the generous free-tier limits provided by Google AI Studio (15 RPM / 1,500 RPD on `gemini-2.0-flash`). |

**Vendor Lock-In Accepted:** Partial — Model layer targets Google Gemini API via official SDK. If another provider is added later, the proxy route pattern in `gemini_routes.js` isolates the client from the rest of the app.

## 3. Framework Quick Reference

### Installation
```bash
npm install @google/generative-ai
```

### Core Imports
```javascript
import { GoogleGenerativeAI } from '@google/generative-ai';
```

### Entry Point Pattern
```javascript
// gemini_routes.js
import { GoogleGenerativeAI } from '@google/generative-ai';

export default function setupGeminiRoutes(app, db) {
  app.post('/api/gemini/chat', async (req, res) => {
    const { message, context = {}, history = [] } = req.body;
    
    // 1. Fetch API key securely from SQLite app_config
    const apiKey = await getApiKeyFromDb(db);
    if (!apiKey) {
      return res.status(403).json({ error: 'API key not configured', unconfigured: true });
    }

    // 2. Initialize Gemini with active context in systemInstruction
    const genAI = new GoogleGenerativeAI(apiKey);
    const model = genAI.getGenerativeModel({
      model: 'gemini-2.0-flash',
      systemInstruction: buildSystemPrompt(context),
    });

    // 3. Start chat with sanitized history
    const chat = model.startChat({
      history: history.map(h => ({ role: h.role, parts: [{ text: h.text }] })),
      generationConfig: { temperature: 0.7, maxOutputTokens: 1024 },
    });

    // 4. Send message and return reply
    const result = await chat.sendMessage(message);
    res.json({ reply: result.response.text() });
  });
}
```

### Key Abstractions

| Concept | What It Is | When You Use It |
|---|---|---|
| `GoogleGenerativeAI` | Root SDK client class initialized with API key | Created per-request or cached in route module |
| `getGenerativeModel` | Model factory binding model name & `systemInstruction` | Call per chat invocation to inject live context |
| `startChat` | Session manager maintaining multi-turn conversational history | Call before sending messages to preserve dialogue turns |
| `sendMessage` | Asynchronous method sending prompt and returning response | Main invocation for synchronous text reply |

### Common Pitfalls
1. **History Role Naming:** Gemini requires roles to be strictly `'user'` or `'model'`. Using `'assistant'` (OpenAI standard) throws a schema validation error.
2. **Context Window Flooding:** Passing raw client data (e.g., 500 purchase register rows) in the prompt will hit TPM limits. Only pass high-level metadata (GSTIN, client name, FY, active screen).
3. **Rate Limits (429 RESOURCE_EXHAUSTED):** Free tier is capped at 15 RPM. Need explicit catch block translating 429 into friendly user guidance instead of raw network dump.

### Recommended Project Structure
```
reco-with-vaswani-main/
├── gemini_routes.js                # Backend route handler & Gemini SDK caller
├── server.js                       # Mounts setupGeminiRoutes(app, db)
└── src/
    ├── lib/
    │   └── geminiApi.ts            # Frontend API client (sendChatMessage, saveApiKey)
    └── components/
        ├── SouravChatbot.tsx       # Floating FAB, slide-in drawer & action buttons
        └── SettingsModal.tsx       # Settings -> "AI Assistant" tab
```

## 4. Implementation Guidance

**Model Configuration:**
- **Model:** `gemini-2.0-flash`
- **Temperature:** `0.7` (Balances conversational warmth with statutory precision)
- **Max Output Tokens:** `1024` (Ensures concise, fast answers under 300 words)

**Core Pattern:**
Proxy Pattern through Node.js backend (`POST /api/gemini/chat`). Frontend React client NEVER communicates directly with Google servers; the Express server retrieves the API key from local SQLite `app_config` table and proxies the request.

**Tool / Action Execution:**
Sourav uses an inline action tag syntax for frontend interaction:
- `[ACTION:navigate:reco]` → Navigates to 2B vs Books Reco
- `[ACTION:navigate:ims]` → Navigates to IMS Hub
- `[ACTION:navigate:3b]` → Navigates to GSTR-3B Working Sheet
- `[ACTION:navigate:gstr1]` → Navigates to GSTR-1 Console
- `[ACTION:navigate:notices]` → Navigates to GST Notices & Orders
- `[ACTION:navigate:tds]` → Navigates to TDS Consolidator
- `[ACTION:navigate:tally]` → Navigates to Tally Direct Bridge
- `[ACTION:navigate:incometax]` → Navigates to Income Tax Engine
- `[ACTION:navigate:cma]` → Navigates to Bank CMA Appraisal
- `[ACTION:navigate:finstatements]` → Navigates to Financial Statements
- `[ACTION:navigate:settings]` → Navigates to Settings

Frontend `SouravChatbot.tsx` regex-parses these tags and renders styled interactive pill buttons.

**State Management:**
- Conversational history is maintained in React state (`messages: Array<{ role: 'user' | 'model', text: string }>`) for the active session.
- Gemini API key is persisted in SQLite table `app_config (key, value)`.

**Context Window Strategy:**
Dynamic injection into `systemInstruction`. Never inject changing metadata (like switched client GSTIN) into historical chat bubbles.

## 4b. AI Systems Best Practices

### Structured Output / Action Tag Schema (Zod / TypeScript)
```typescript
import { z } from 'zod';

export const ActionTagSchema = z.object({
  type: z.literal('navigate'),
  target: z.enum([
    'reco', 'ims', '3b', 'gstr1', 'notices', 'tds', 
    'tally', 'incometax', 'cma', 'finstatements', 'settings'
  ])
});

export type ActionTag = z.infer<typeof ActionTagSchema>;

export function parseActionTags(text: string): { cleanText: string; actions: ActionTag[] } {
  const actions: ActionTag[] = [];
  const regex = /\[ACTION:navigate:([a-z0-9_-]+)\]/g;
  let match;
  while ((match = regex.exec(text)) !== null) {
    const parsed = ActionTagSchema.safeParse({ type: 'navigate', target: match[1] });
    if (parsed.success) actions.push(parsed.data);
  }
  const cleanText = text.replace(regex, '').trim();
  return { cleanText, actions };
}
```

### Async-First Design
- Backend uses `async/await` throughout route handling with timeout guards.
- Frontend manages loading states (`isLoading = true`) and provides an animated 3-dot typing indicator.

### Prompt Engineering Discipline
- Explicit role boundaries in `systemInstruction`.
- Negative constraints: "Never invent section numbers", "Keep answers under 300 words", "Never reveal internal API keys or database passwords".
- Multilingual instructions: "Detect language automatically; answer in Hinglish if asked in Hindi/Hinglish; answer in formal CA English if asked in English".

### Cost and Latency Budget
- Free Tier: $0 cost.
- Latency target: p50 < 1.8s, p95 < 3.5s on `gemini-2.0-flash`.
- Token budget: Input context ~600 tokens (system prompt + active client + history), output ~150-300 tokens per turn.

### Dimensions

| Dimension | Rubric (Pass/Fail or 1-5) | Measurement Approach | Priority |
|---|---|---|---|
| **Statutory Correctness** | Pass/Fail: Must accurately cite relevant CGST/SGST/IGST sections without hallucinating fictional laws. | Automated Benchmark Suite (25 Gold standard tax scenarios) | **Critical** |
| **Action Tag Validity** | Pass/Fail: Every emitted `[ACTION:navigate:xxx]` must match a registered route in `ActionTagSchema`. | Automated Regex / Schema Validator | **Critical** |

## 6. Guardrails

### Online (Real-Time)

| Guardrail | Trigger | Intervention |
|---|---|---|
| **API Key Missing Guard** | Unset `gemini_api_key` in SQLite `app_config` | Returns HTTP 403 with `{ unconfigured: true }`; UI displays inline setup banner |
| **Action Tag Sanitizer** | Action token target not in registered whitelist | Regex strips invalid action token before UI rendering |
| **Quota Throttling Guard** | Gemini API returns HTTP 429 / `RESOURCE_EXHAUSTED` | Intercepts error and displays: *"Gemini free quota reached. Please wait a minute or upgrade your key."* |
| **PII / Secret Shield** | Prompt or output contains `SELECT * FROM network_users` or DB connection string | Blocks output; logs security warning |

### Offline (Flywheel)

| Metric | Sampling Strategy | Action on Degradation |
|---|---|---|
| **Statutory Benchmark Pass Rate** | Run 25-item eval test suite before each build | Blocks `npm run build:exe` if pass rate < 100% on statutory items |
| **Action Route Accuracy** | Validates all deep-link targets against current AppShell routes | Alert if an action target points to a deprecated or renamed tab |

## 7. Production Monitoring

**Tracing & Logging:**
Local structured logging in `server.js` console output with `[Sourav AI]` prefix (timestamp, prompt tokens, completion tokens, latency ms).

**Key Metrics to Track:**
1. Daily query volume (requests/day vs 1,500 free tier limit).
2. Latency percentiles (p50, p95).
3. 429 Rate limit frequency.
4. Error rate (invalid API keys, network dropouts).

**Alert Thresholds:**
- Consecutive 429 responses > 3: Display persistent amber warning in chat drawer.
- Backend timeout > 10s: Display retry prompt.

**Smart Sampling Strategy:**
Failed queries and rate-limit hits are logged to local SQLite `tasks` or server console for diagnostic review without transmitting client chat transcripts off-device.
