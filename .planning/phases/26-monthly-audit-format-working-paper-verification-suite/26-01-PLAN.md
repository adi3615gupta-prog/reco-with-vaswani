<objective>
Implement the SQLite database schema, persistence layer, and REST API routes for the Monthly Audit Working Paper & Verification Suite (`monthly_audit_routes.js`, registered in `server.js`).

Purpose: Establish a local-first, audit-grade repository for monthly audit engagement details, 8 verification checklists, categorized observations, cross-month pending work trackers (modeled on `Work Pending List.xlsx`), live verification snapshots, and direct client directory auto-save.
Output: `monthly_audit_routes.js`, modifications to `server.js`, and comprehensive Vitest tests in `src/test/monthlyAuditBackend.test.ts`.
</objective>

<context>
The CA firm audit format (`\\new_server\D\3. 2025-2026\DYP Infraprojects Private Limited\Monthly Audit Format.docx`) and cross-month pending points tracker (`Work Pending List.xlsx`) require five core data stores:
1. `monthly_audits`: Header metadata (Client, Auditor, Team members JSON array, Audit Type, FY, Month, Gross Turnover inc GST, Books vs GST turnover, fieldwork start/end dates, status `Draft` | `In Progress` | `Under Review` | `Completed`).
2. `audit_checklists`: Sr. No. 1 to 8 standardized verification items (Sales/Purchase vouching, Key workings: GST 3B/R1, 2B, TDS 24Q/26Q, Depreciation, Provisions, Cash 40A(3), ROC charges, AIS/TIS, Fixed Assets ITC, Labor compliances) with Status, Sample %, Remarks, Amount involved.
3. `audit_observations`: Current year audit observations categorized by risk (Critical, High, Medium, Low, Info) with financial exposure, voucher reference, auditor recommendation, and management response.
4. `audit_pending_points`: Persistent action tracker carried forward across months with status transitions (`Pending` -> `In Progress` -> `Cleared`), resolution remarks, target date, and verifying auditor.
5. `audit_verification_data`: JSON snapshot cache of automated scans (Sales Books vs R1 vs 3B, Purchase Books vs 2B, Cash 40A(3) violations, PF/ESIC/PT wages and deposit dates, Bank/Loans/ROC).

Auto-save writes directly into: `gst_returns_data/<Client Name - GSTIN>/<FY>/<Month>/Audit Working/Monthly_Audit_Working_Paper_{Client}_{Month}.xlsx`.
</context>

<threat_model>
<threat>
  <id>T-26-01</id>
  <description>SQL injection vulnerability in audit filtering, checklist updates, or observation queries leading to unauthorized data alteration or deletion.</description>
  <mitigation>All SQL statements strictly use parameterized SQLite queries (`?` placeholders) with no string interpolation of user-supplied inputs.</mitigation>
</threat>
<threat>
  <id>T-26-02</id>
  <description>Path traversal vulnerability when saving Excel working paper to client audit directory allowing arbitrary file overwrites.</description>
  <mitigation>Sanitize client name, GSTIN, FY, and Month parameters, resolving paths strictly within `gst_returns_data/` using path.resolve and verifying target directory confinement.</mitigation>
</threat>
<threat>
  <id>T-26-03</id>
  <description>Dangling checklist items or observations upon audit deletion or client record changes.</description>
  <mitigation>Use FOREIGN KEY (audit_id) REFERENCES monthly_audits(id) ON DELETE CASCADE and enable PRAGMA foreign_keys = ON.</mitigation>
</threat>
</threat_model>
