  <mitigation>Deterministic date arithmetic parsing YYYY-MM-DD or DD/MM/YYYY into standardized UTC midnight timestamps with explicit form-specific offset rules (+7d for DRC-01B/C, +30d for ASMT-10/DRC-01).</mitigation>
</threat>

    1. In `notices/db.js`, refine `computeLimitationDueDate(noticeType, issueDate)`:
       - If `noticeType` is `DRC-01B` or `DRC-01C`: Add exactly 7 days to `issueDate`.
       - If `noticeType` is `ASMT-10`, `DRC-01`, `DRC-01A`: Add exactly 30 days to `issueDate`.
       - For other notice types (REG-03, REG-17, ASMT-13): Support explicit days parameter with 15-day fallback.
       - Normalize all dates to standard `YYYY-MM-DD` strings.
    2. Implement `getNoticeAlertStatus(dueDate)`:
       - Calculate remaining calendar days from current local date.
       - If remaining < 0: return `{ status: 'EXPIRED', daysRemaining: remaining, badgeColor: 'crimson' }`.
       - If remaining <= 3: return `{ status: 'CRITICAL', daysRemaining: remaining, badgeColor: 'red' }`.
       - If remaining <= 7: return `{ status: 'URGENT', daysRemaining: remaining, badgeColor: 'amber' }`.
       - Else: return `{ status: 'NORMAL', daysRemaining: remaining, badgeColor: 'emerald' }`.
  </action>
